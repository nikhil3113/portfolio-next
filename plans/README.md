## Findings considered and rejected

These were audited and deliberately not turned into plans. Do not re-audit them
without new evidence.

- **`proxy.ts` instead of `middleware.ts`** — correct for Next.js 16; middleware
  was renamed to proxy.
- **React 18 with Next 16** — Next 16.4.6 still declares `react: ^18.2.0 || ^19`,
  so there is no concrete break.
- **`findUnique` with `isPublished` in the where clause** — Prisma 5+ supports
  extended unique filters; this is valid.
- **Throttling the view counter** — the metric is cosmetic and there is no shared
  store after the Redis removal. Only the 404/published validation is folded into
  plan 012; a distributed limiter is deferred.
- **`dangerouslyAllowSVG` on its own** — only material because unauthenticated
  uploads exist. Plan 001 adds the image CSP; plan 004 authenticates the
  Cloudinary endpoint.
- **`@typescript-eslint` clusters** — no standalone plan; lint triage in 002 and
  the touched files in later plans handle them.
- **A global error boundary** — not planned; the three known states are handled in
  008. A route-level `error.tsx` is a follow-up if a fourth state appears.

## Additional verified finding

While verifying the blog renderer, the audit confirmed that
`app/blogs/[slug]/page.tsx` calls `cheerio.load(blog.content)` and then
`$.html()`, which serializes a full document (`<html><head></head><body>…`) into
the article's `<div>`. That is invalid markup. Plan 006 fixes it by loading the
content as a fragment (`cheerio.load(content, null, false)`). It was not in the
original findings table because it was found during plan verification.
